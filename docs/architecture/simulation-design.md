# Simulation Design

All values are generated by software models. They are simplified engineering approximations with plausible behaviour, and they are not calibrated against any real machine.

## Rotating machines (motor, conveyor, robot, pump)

Integrated with explicit Euler at 1 s. Variables: speed fraction `s`, load `L`, wear `w`, cooling factor `c`.

| Quantity | Model |
| --- | --- |
| Speed | First-order response to the command, 8 s time constant |
| Shaft fraction | `L * s * (1 + 0.2 w)`; pumps use `s^3` and a leak term |
| Electrical power | `P_rated * shaft / efficiency` |
| Current | `P / (sqrt(3) * V * pf)` |
| Losses | `0.027 P_rated s + 0.085 P_rated shaft^2` |
| Winding temperature | `C dT/dt = losses - h c (T - T_ambient)` |
| Bearing temperature | First-order towards `T_ambient + 18 s + 45 w s` |
| Vibration RMS | `0.9 + 0.7 s^2 + 8.5 w^2 s` |
| Wear | `dw/dt = (1e-8 + r (1 + 4 w)) s^2`, with `r` raised by the fault |

A machine fails when wear reaches 1 or the winding reaches 140 °C.

The reported health sensor is derived from vibration and temperature, as a real self-diagnostic would be. It never reads the hidden wear state.

## Other assets

| Asset | Model |
| --- | --- |
| Pump | Affinity laws for flow and head. A discharge leak lowers pressure and delivered flow, and raises suction flow |
| Tank | Mass balance with a proportional level controller on the outlet valve |
| Power unit | Sums downstream load, with bus voltage droop and a first-order transformer temperature |
| Environment | Diurnal ambient temperature with slow stochastic drift. Humidity follows temperature |

## Sensors

`reading = gain * true + offset + noise + attack`, then clipped to range and quantised. Each signal has redundant sensors on separate devices.

## Scenarios

| Scenario | Effect |
| --- | --- |
| `bearing_degradation` | Raises the wear rate |
| `motor_overheating` | Ramps the cooling factor down |
| `pump_leakage` | Ramps a discharge leak up |
| `gateway_outage` | Gateway process down: telemetry lost, edge policies stopped |
| `network_degradation` | Adds latency and packet loss |
| `sensor_manipulation` | Ramps a false bias onto one sensor |
| `sensor_replay` | Freezes one sensor's value |
| `central_disconnection` | All uplinks down: edge continues, telemetry buffers |
| `telemetry_backlog` | Long uplink loss, then bounded-rate flush |

Attacks are simulator state only. There is no real network attack code in this project.

## Reproducibility

`SeedSequence.spawn` gives each machine, sensor, gateway and the ambient model its own stream. A headless run with a given seed is byte-identical, which a test enforces. Live runs use the wall clock for timestamps, and operator actions arrive at unpredictable simulation times, so live runs are not byte-identical.

## Scaling

`build_factory(scale=5)` produces 500 devices. The layout is tested at that size, and the engine alone ran at about 375x real time there. The full live stack has not yet been benchmarked at 500 devices.
